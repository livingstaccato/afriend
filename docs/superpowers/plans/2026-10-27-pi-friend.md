# Pi Friend Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this
> plan task by task. Request an independent code review with
> superpowers:requesting-code-review before declaring completion. This plan is
> saved for review; do not start execution until the user resumes the work.

**Goal:** Ship Pi as a fully integrated friend, with automated regression
coverage and recorded evidence from real Pi reviews.

**Architecture:** Add a canonical adapter to the existing execution pipeline.
Extend shared envelope or model-list parsing only when real Pi output requires
it. Discovery, provider configuration, orchestration, status, resume, and
packaging continue to consume the registry through existing interfaces.

**Tech stack:** Python >=3.11, stdlib-only runtime, TOML adapters, pytest,
uv, existing plugin projection tooling, installed Pi CLI.

## Global constraints

- Approved design: `docs/superpowers/specs/2026-10-27-pi-friend-design.md`.
- No new runtime dependency, release/version bump, publishing, or unrelated
  refactoring.
- Canonical assets live in `src/afriend/assets/`; never edit generated
  `plugins/afriend/skills/` directly.
- Preserve the 777-line per-file cap; `adapters.py` already has little room.
- Tests must never accidentally discover real model CLIs or invoke metered
  models. Real model calls belong only to explicitly executed live validation.
- Use temporary state for unauthenticated and malicious-configuration probes.
  Do not modify or log the operator's credentials, settings, or sessions.
- Required deny flags must fail closed on unsupported Pi versions. A help
  probe verifies flag support; it does not prove behavior by itself.
- Record unavailable platform coverage and unsuccessful live calls as gaps.
  Simulated Pi output is automated coverage, never live proof.
- A passing gate means the expected exit status and persisted outcome agree;
  a seeded blocking finding should make gate exit nonzero.
- After writing this plan, pause. No implementation or live calls have been
  authorized for this stage after the user's pause instruction.

## Observations from planning

`pi --version` reports `1.4.0`. `pi --help` advertises `--print`, `--mode
json`, `--no-session`, `--model`, `--thinking`, `--tools`, `--no-tools`,
`--no-extensions`, `--no-mcp`, `--no-skills`, `--no-prompt-templates`,
`--no-themes`, `--no-context-files`, `--no-approve`, and `--list-models`.
Its help warns that `--tools` alone keeps MCP tools unless explicitly
addressed. Do not treat a read-only tool allowlist as an MCP denial.

Help also produced a settings-lock warning under the current execution
sandbox. Startup may require writable private state even when no session is
saved. This must be resolved and measured, not hidden with a broad write grant.

The local executable is a managed shell launcher at
`~/.pi/agent/bin/pi`. It reads `install/current-version`, launches the
corresponding release, and may prepend
`${XDG_DATA_HOME:-$HOME/.local/share}/pi-node/current/bin` to PATH. A confined
run must account for this real launcher, not just an npm executable in isolation.

`Envelope` currently supports dotted object paths and NDJSON rules with a
secondary equality condition, plus a terminal event. List-valued extraction
currently wraps an array under its field name; it does not select text blocks.
`models_format` accepts only `lines` or `tsv`, neither of which can be assumed
correct for Pi's listing. No success/error/model-list events have been captured
in this planning stage.

Explicit `--host-provider pi` can use the registry-based host contract once the
adapter exists. Add automatic detection only if a genuine Pi child-process
marker is observed; `PI_CODING_AGENT_DIR` is configuration, not proof of a host.

## File ownership and interfaces

| Area | Files | Responsibility |
| --- | --- | --- |
| Adapter | `src/afriend/assets/adapters/pi.toml` | Verified invocation, authority, effort, envelope, environment and confinement declarations |
| Output extraction, if needed | `src/afriend/envelopes.py`, `src/afriend/normalize.py` | Declarative extraction from actual Pi events; avoid provider-name branches |
| Model inventory, if needed | `src/afriend/models.py`, `src/afriend/adapters.py` | Parse actual listing into qualified executable model IDs; validate any new format |
| Host/readiness, if needed | `src/afriend/readiness.py` | Verified automatic host marker and existing fail-closed capability probe |
| Runtime environment, if needed | `src/afriend/childenv.py`, `src/afriend/sandbox.py` | Narrow startup access and private state; only change shared behavior for a measured need |
| Focused tests | `tests/test_pi_adapter.py`, `tests/test_pi_envelope.py`, `tests/test_models_listing.py`, `tests/test_readiness.py`, `tests/test_fresh_host_worker.py` | Adapter contract, extraction, inventory, readiness and host roles |
| End-to-end tests | `tests/test_run_end_to_end_pi.py`, `tests/pi_cli_stub.py` | Pi-shaped process boundary through actual adapter dispatch in every mode |
| Captured fixtures | `tests/fixtures/pi/` | Sanitized real stdout/stderr and provenance; constructed cases labeled separately |
| Packaging | `ci/verify_wheel_install.sh` | Installed wheel must expose Pi outside the checkout |
| Product docs | `README.md`, `docs/installation-troubleshooting.md`, canonical review/configure skill references | Usage, constraints, model inventory, host selection and measured pitfalls |
| Projection | `plugins/afriend/skills/` | Generated by `make plugin-sync-copy` |
| Evidence | `docs/superpowers/reviews/2026-10-27-pi-friend-verification.md` | Commands, versions, outcomes, artifact references and platform gaps |

Existing interfaces to retain:

```python
load_adapters(directory: Path) -> dict[str, Adapter]
list_models(adapter: Adapter, *, timeout_s: int = 30) -> ProviderModels
unwrap_envelope(raw: str, envelope: Envelope) -> str | None
envelope_error(raw: str, envelope: Envelope) -> str | None
answer_is_complete(text: str, envelope: Envelope) -> bool
detect_host(env: Mapping[str, str], *, host_provider: str | None = None) -> str | None
```

No public Pi-specific transport or command is needed.

### Task 3: Normalize Pi answers and expose a usable model inventory

**Files:** Create `tests/test_pi_envelope.py`; add sanitized fixtures under
`tests/fixtures/pi/`. Modify shared parsers and their existing tests only if
the current declaration language cannot express the captured output.

**Consumes:** Real event/listing fixtures and Task 2 adapter.
**Produces:** Reliable findings/verdict normalization and qualified model IDs.

- [ ] Add fixture-based tests through the shipped adapter and real normalizer:

  ```python
  from pathlib import Path
  from afriend import adapters, normalize
  from afriend.paths import ADAPTER_DIR

  def test_pi_real_review_event_reaches_findings():
      adapter = adapters.load_adapters(ADAPTER_DIR)["pi"]
      raw = (Path(__file__).parent / "fixtures/pi/review.ndjson").read_text()
      result = normalize.normalize(
          raw, envelope=adapter.envelope,
          structured_output=adapter.structured_output,
      )
      assert result.succeeded, result.errors
      assert result.payload is not None
      assert result.payload["findings"]
  ```

  Independently assert the captured finding's literal claim/location and the
  verdict fixture's literal claim IDs with `VERDICT_CONTRACT`. Observe the
  failing extraction before changing the parser.
- [ ] Add constructed regressions for text split across blocks, reasoning that
  contains a plausible findings object, user/tool-result decoys, progress before
  final answer, partial lines, provider failure, and terminal events. Assert
  `unwrap_envelope` itself excludes decoys; permissive raw fallback in normalize
  must not mask a broken extraction test. Decide with a failing regression
  whether Pi requires a narrower fallback boundary to prevent accepting an
  echoed prompt as its answer.
- [ ] If necessary, add a small generic declaration for selecting text blocks
  from event content arrays, filtering by the actual text-block discriminator.
  Join blocks in message order, preserve latest-answer precedence, and keep
  existing list extraction for `findings` unchanged. Validate malformed selector
  declarations at adapter load time. Keep any extra helper module focused if
  the existing file would exceed the line cap.
- [ ] Prove terminal detection distinguishes a complete Pi turn from an
  intermediate message/tool event and does not truncate a streamed answer.
  Assert real error messages reach existing failure classification without
  being mistaken for findings.
- [ ] Add model-list fixture tests for provider qualification, duplicate model
  IDs across providers, whitespace/headers/ANSI, empty/error output, and the
  existing inventory cap. The expected IDs must be literal hand-checked values.
  If a new format is required, extend `_parse` and the adapter format validator;
  update `test_the_shipped_adapters_declare_only_supported_formats` accordingly.
  Do not return unsupported inventory merely to avoid implementing a measured
  Pi listing format.
- [ ] Run focused Pi/envelope/model tests, then all existing normalize/envelope,
  provider-error and model-list command tests. Preserve other adapters' behavior.
