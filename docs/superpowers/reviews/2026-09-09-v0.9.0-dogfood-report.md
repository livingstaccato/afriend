## Finding

One claim, `c-0001@1`, high severity, raised by `agy/assumptions`.

**Claimed:** the `verdicts_already_durable` early return in
`judgebatch.recover_judging_batch` lets an attacker who forges verdicts in
`claims.jsonl` have a judge skipped, accepting the forged verdicts unchecked.

**Verified, and recorded as rejected.** The claim is partly right and its fix
does not work:

- The mechanism is real. `crossexam.py:281` does `if not slice_: continue`,
  and `slice_` excludes claims with a durable verdict, so forged durable
  verdicts do suppress re-dispatch.
- It is not a 0.9.0 regression. `git log -S legacy_complete` puts the early
  return at `1d3bc1f`, the package rename. This release only renamed the
  parameter.
- The suggested fix is ineffective. `judgebatch.py:78` returns `None` at the
  file-existence check *before* the version branch, so deleting the audit
  file — which the claim itself offers as an alternative — reaches the same
  skip with the early return removed.

The underlying gap is that `claims.jsonl` is replayed with no integrity check
while `run.json` is validated as hostile input throughout. Filed as
[#5](https://github.com/livingstaccato/afriend/issues/5).
