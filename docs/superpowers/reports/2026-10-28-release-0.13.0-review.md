## Findings and remediation

### P2: Pi custom state did not match confined credential grants

**Confidence:** high. **Origin:** newly added Pi adapter in `5b9e0b5`.

The adapter passed `PI_CODING_AGENT_DIR`, but confinement granted only the default
`~/.pi/agent/auth.json` and `models.json`. With a custom directory outside the
other grants, Pi could not find its models or authenticate. Installed Pi 1.4.0's
`dist/config.js` derives both file paths from `getAgentDir()`; policy construction
previously had no corresponding runtime reads.

`src/afriend/dispatch.py` now derives the effective directory from the filtered
child environment, replaces default credential grants with the exact two files,
and retains the managed-install grants. Relative values resolve against the
friend's cwd and the same absolute directory reaches the child. Tilde/file URLs
and literal dollar signs follow the supported Pi path semantics. Directory and
symlink-to-directory endpoints are excluded to avoid unintended subtree grants.
Settings, sessions, extensions, and the state root receive no additional grant.

**Evidence:** `tests/test_pi_confinement.py` first failed on redirected grants;
all ten cases pass after repair. The relative-path assertion also failed before
normalizing the child environment. The test constructs the real policy and
Seatbelt profile while substituting process execution; it does not prove kernel
confinement in this environment. Final independent security re-review found no
blocker and confirmed the relative-path concern closed.

### P2: Pi answers beyond two content slots were dropped

**Confidence:** high. **Origin:** newly added Pi envelope rules in `5b9e0b5`.

The declared rules inspected only `content[0].text` and `content[1].text`.
Provider content can contain multiple thinking blocks, including redacted
thinking exposed by Pi as another thinking block, before text. Such a successful
answer was reported as absent. Multiple text blocks also needed reconstruction.

`src/afriend/envelopes.py` now supports a declarative `[*]` string extraction,
joining matching text fields in content order without inserting separators.
Pi uses `message.content[*].text`; the `stopReason == "stop"` gate and latest
message precedence remain intact.

**Evidence:** both new canonical-adapter regressions in
`tests/test_envelope_fixtures.py` failed before repair and pass afterward,
including JSON divided over three text blocks. Five mechanism cases in
`tests/test_envelope_rule_conditions.py` cover ordering and non-string/absent
content. Existing aborted, no-text, auth-error, and other-provider cases pass.
These extra block-layout cases are synthetic, not newly captured provider calls.

## Historical context and variant analysis

No removed security check from a prior security-fix commit was identified.
OpenCode's log grant remains limited to its log subdirectory, and its explicit
external-tool authorization policy is unchanged. Pi still requires outer
confinement, a read-only workdir, tool allowlisting, and six extension/context
resource denial flags.

Searching other adapter answer paths found no other fixed-slot content extractors.
The custom-state pattern has pre-existing counterparts: external
`OPENCODE_CONFIG`/`OPENCODE_CONFIG_DIR` paths and an explicitly forwarded
`CODEX_HOME` are not dynamically added to confinement grants. OpenCode's HOME
fallback also does not repair custom `XDG_CONFIG_HOME` setups. Those limitations
already existed on the baseline and remain follow-up work; this release does not
claim to support them. Default-path configurations are unaffected by those cases.

Pi model enumeration initializes its runtime before listing; resource trust checks
remain in Pi. Omitting denial flags from inventory is a possible hardening task,
not a demonstrated exploit found by this review. No vulnerability was inferred
merely from this initialization behavior.
